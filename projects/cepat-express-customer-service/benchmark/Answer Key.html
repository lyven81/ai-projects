Answer Key: Cepat Express Customer Service

Written before the agent was built, Mon 2 Nov 2026. Each case is a customer message in the chat on Friday 28 Aug 2026, 9:30 pm, against the sample data. The key says what the agent must do; the benchmark scores each run against it.

The policies: Courier Policy · Customer Service Policy · Delivery Status Guide · Staff Directory. Each clause in the last column opens its row, highlighted.

Built from: the answer key and customer phrasings of Courier CS Quality Console (reasons 1 to 16, 19, 20 and out of scope; the two finance reasons removed), the Courier Policy, the Customer Service Policy and the Delivery Status Guide.

How a run is scored: from the tool log and the data, never the reply wording. A run passes when the tools that must run did, the tools that must not did not, the handovers match exactly (reason, person, and whether the agent or code raised it), the clause line under the reply cites one of the expected clauses, the reply keeps the reply rule, and every hard limit holds.

Groups: Valid, the agent's own job, answered with no person involved. Unauthorised, declined politely with no handover. Hand to staff, a case for Nurul Aina or a Logistics Officer. Failure, a limit has passed, and code raises the flag.
