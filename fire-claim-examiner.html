Fire Policy Underwriter Advisor

Live demoGitHub

By Lee Yih Ven · Published 7 November 2026

Designed for a fire insurance claims desk, where a claims examiner decides each claim from the claimant's account, the loss adjuster's report and the policy schedule. A fire policy is a base wording plus the endorsements on each schedule that vary it, so the answer turns on which clause governs. The facts are tested against the wording gate by gate, and the loss is priced in a fixed order.

I built an AI underwriter that reads the claim file and advises the claims examiner gate by gate, while code sets every gate status and the figure. The system reviews 22 claims across 11 perils. It retrieves the policy wording by clause code or in plain words, and ranks a plain-words search by authority.

The decision stays with the claims examiner, who also receives every point the policy leaves open, such as a building that does not fit the endorsement it holds. In testing, the system passed all 22 claims, covering approvals, declines at each gate and flagged claims. Read every claim file with its advice on the claim file page.

One Claim, From the Claim File to the Examiner

One claim from the claim file to the examiner's decision: the Kuantan burst pipe. The six gates, in order: 1. Period of insurance, 2. Peril insured, 3. Conditions precedent, 4. Endorsement held, 5. Endorsement satisfied, 6. Item admitted. Left out here: the search for each clause and each gate's facts (in the Technical tab and the claim file's Under the hood tab).

  1. The claims examiner opens the claim file: the claimant's account, the adjuster's report and the policy schedule. The AI underwriter reads all three and names the cause of the loss from the adjuster's findings. It looks up the policy wording and gives each fact with the document it came from.
  2. Code checks the six gates in order, on wording looked up for this claim, and the first gate that fails stops the chain unless that gate is re-checked. A building that does not fit the endorsement it holds passes with a flag for the examiner.
  3. Code then prices the claim: exclusions first, then average on each item, then the excess.
  4. Before the advice reaches the examiner, code checks every quote, status, the governing clause and the amount. A line that does not match goes back to the AI underwriter to fix; after two retries the claim goes to the examiner without advice. The claims examiner reads the advice and decides, including any flag.

What It Does for the Claims Desk

The clause that governs, ranked by authority

A plain-words search ranks an endorsement on the claim's schedule above the exclusion it displaces, and marks one not held as unable to override, as the Under the hood tab shows on seven claims. A building that does not fit the variant held is flagged for the examiner, never refused. The advice quotes only wording returned for that claim, word for word.

Six gates in order, each status set in code

The six gates run in order, and the first that fails stops the chain unless it is re-checked with corrected facts. The underwriter gives each fact with the document and section it came from, and names the cause of the loss from the adjuster's findings. Where the accounts differ, the advice names both and applies the adjuster's finding: in one storm claim the claimant blamed wind-blown tiles, and the adjuster found no tile missing and an overflowing gutter.

A figure the examiner can check line by line

Code removes the excluded items first, then cuts each item insured below its value in proportion (average), then takes the excess. Where there is a basis to price it, a declined claim shows what the policy would have paid but for the deciding ground, marked not payable. The working sits beside the advice on every claim file.

Tools, Resources and Workflow

How the AI works

The loop reads the three claim resources and gives them to the underwriter with the system prompt, which is cached between calls. The underwriter searches the wording for each gate, calls check_gate with the facts, then calculate_payable, then submit_advice. The loop ends when the advice is recorded, when the guard rejects it after two retries, or at 40 turns.

The six gates

The first gate that fails decides; gates after it are not reached unless the failed gate is re-checked with corrected facts, and a re-check clears every gate after it. 1. Period of insurance; 2. Peril insured; 3. Conditions precedent; 4. Endorsement held; 5. Endorsement satisfied; 6. Item admitted. At gate 2 the underwriter names the cause from the adjuster's report, as one of 18 causes in the rules file, and code tests whether the policy insures it anywhere, base cover or any endorsement. At gate 6 each item claimed is classed into one of 12 categories, and code decides from the category and the clause that answers the cause whether it is admitted.

Code Walkthrough

Precedence: the Clause That Governs Ranks First

After the rerank, candidates are ordered by legal authority against the open claim's schedule. An endorsement that is not held cannot override.

# engine/retrieval.py: search, stage 3
        # stage 3: precedence, applied ONLY among clauses in contention
        peril = peril or self.infer_peril(query)

        for c in cands:
            eff, note = c["authority"], ""

            # Is this clause even about the question asked? A clause tagged to
            # a different peril is not competing; promoting it on authority
            # ranked flood and earthquake above storm on a storm query.
            on_topic = (c["peril"] is None) or (peril is None) or (c["peril"] == peril)
            c["on_topic"] = on_topic

            if c["type"] == "coverage_decision":
                # Carries both the base position and the override plus the rule
                # for choosing between them, so it answers either way.
                note = (f"{c['code']} held: override applies" if c["code"] in held
                        else f"{c['code']} not held: {c['overrides']} stands")
            elif eff == "override" and c["code"] and c["code"] not in held:
                eff, note = "informational", "not held: cannot override"

            c["effective_authority"] = eff
            c["authority_note"] = note
            # off-topic clauses are ranked on relevance alone, never promoted
            c["authority_rank"] = AUTHORITY_RANK[eff] if on_topic else 9
            c["tier_bias"] = 0 if (on_topic and c["type"] == "coverage_decision") else 1

        cands.sort(key=lambda c: (not c["on_topic"], c["authority_rank"],
                                  c["tier_bias"], -c["rerank_score"]))
        return cands[:k]

Order Is Enforced in Code

Before any gate runs, code checks that every earlier gate passed. After a failure, nothing later is reached.

# engine/gates.py: _order
    def _order(self, gate: int):
        if gate not in NAMES:
            raise GateError("gate_out_of_order", f"There is no gate {gate}; gates run 1 to 6.")
        for g in range(1, gate):
            r = self.results.get(g)
            if r is None:
                raise GateError("gate_out_of_order",
                                f"Gate {g} ({NAMES[g]}) must be checked before gate {gate}.",
                                next_gate=g)
            if r.status == "fail":
                raise GateError("chain_stopped",
                                f"Gate {g} failed; gates after it are not reached. "
                                "Call calculate_payable, then submit_advice.", failed_gate=g)
        # re-checking a gate discards everything after it
        for g in [k for k in self.results if k >= gate]:
            del self.results[g]
        self.payable = None

Gate 4: a Flag, Never a Fail, for a Variant Mismatch

The endorsement that answers the cause must be on the schedule. A paired variant that does not fit the building passes with a flag for the examiner.

# engine/gates.py: _gate_4
    def _gate_4(self, raw):
        R = RULES["gate_4"]
        f = _values(raw, R["required_facts"])
        held = [str(c).strip() for c in (f["endorsements_held"] or [])]
        self.held = held
        spec = RULES["gate_2"]["causes"][self.cause]
        if spec["base"]:
            self.answer = "BASE"
            return GateResult(4, "pass", "Operative clause",
                              "No endorsement is required for a base peril.")
        cands = [c for c in spec["insured_by"] if c in held]
        if not cands:
            self.answer = None
            base_ex = spec.get("base_exclusion")
            return GateResult(4, "fail", base_ex or f"{' or '.join(spec['insured_by'])} not held",
                              f"{' or '.join(spec['insured_by'])} is not on the schedule"
                              + (f", so {base_ex} stands" if base_ex else "")
                              + ". The loss is not covered.")
        variants = R["variants"]
        fitting = [c for c in cands if c not in variants or self._fits(c, f)]
        chosen = fitting[0] if fitting else cands[0]
        self.answer = chosen
        self._need([f"ENDORSEMENT-{chosen}"])
        if chosen in variants and not self._fits(chosen, f):
            other = [v for v in variants if v[:-1] == chosen[:-1] and v != chosen]
            flag = (f"Building class mismatch: {chosen} is held, but the building does not fit its scope. "
                    f"The variant that fits is {other[0] if other else 'another variant'}.")
            return GateResult(4, "pass_flagged", chosen,
                              f"{chosen} is on the schedule and responds on its wording. {flag} "
                              "Flagged for the claims examiner to decide.", flags=[flag])
        return GateResult(4, "pass", chosen, f"{chosen} is on the schedule and answers the cause.")

The Figure, in a Fixed Order

Exclusions are removed first, average is applied to each schedule item, and the excess is taken after average.

    payable = 0.0

        after_avg = 0.0

Empty Is an Answer; Down Is an Error

Search returns only passages the reranker finds relevant, and a search that cannot run raises a retryable error instead of an empty list.

# engine/policy_search.py: search
    def search(self, query: str, held: list[str], k: int = 4) -> list[dict]:
        try:
            res = self.retriever.search(query, set(held), k=40, pool=25)
        except SearchUnavailable:
            raise
        except Exception as e:
            raise SearchUnavailable(f"Policy search failed: {e}. Retry.")
        # Precedence orders clauses competing on one peril. A query on no peril
        # (notice, occupancy, money) is ranked on relevance alone.
        if self.retriever.infer_peril(query) is None:
            res = sorted(res, key=lambda r: -r["rerank_score"])
        out, seen = [], set()
        for r in res:
            if r["rerank_score"] < MIN_RERANK:
                continue
            if r["type"] == "coverage_decision":
                # a decision node stands for its endorsement: return that instead
                is_held = r["code"] in set(held)
                r = dict(BY_ID.get(f"ENDORSEMENT-{r['code']}", r),
                         effective_authority="override" if is_held else "informational",
                         authority_note="" if is_held else "not held: cannot override")
                if r["type"] == "coverage_decision":
                    continue
            if r["chunk_id"] in seen:
                continue
            seen.add(r["chunk_id"])
            out.append(trim(r))
        return out[:k]

Claude Haiku 5.5; Claude Sonnet 5.5 on one claim		Reads the three documents, searches the policy wording, names the cause of the loss from the adjuster's findings, supplies each gate's facts with their source, classes each item claimed, explains the wording and the working, and writes the advice.
Code: retrieval
engine/retrieval.py, engine/policy_search.py		Returns the wording for the open claim, a plain-words search ranked by authority against its schedule; logs every chunk returned.
Code: the gates and the figure
engine/gates.py, engine/calculator.py, rules/condition_tests.json		Sets every gate status and every figure, in order, from the facts given and the wording retrieved.
Code: the guard
engine/guard.py		Records the advice only when every quote, status, the governing clause and the figure match what code set; names the failing line otherwise.
The claims examiner
Outside the system		Reads the claim file and the advice, takes every flag, and decides.

GitHub Repository

The code that decides how the system behaves, cut directly from the project files. The AI reads the claim file, chooses what to search and supplies facts; retrieval, the gates, the calculator and the guard decide what is recorded. Page markup is left out. View the code on GitHub.

projects/fire-claim-examiner/
├── cases/                    # 22 claim files: incident.md, adjuster.md, schedule.md, expected.json
├── data/chunks.json          # 117 clause-level chunks of the policy wording, scope notes included
├── rules/condition_tests.json # The gate tests as data: causes, variant scopes, gate 5 tests, item rules
├── engine/
│   ├── retrieval.py          # Vector and keyword pools, rerank, precedence by authority
│   ├── policy_search.py      # Search scoped to the open claim: empty result, retryable error, lookup
│   ├── gates.py              # The six gates in order, the item rules, the figure
│   ├── calculator.py         # Exclusions, average per item, excess after average
│   ├── guard.py              # The check on the advice before it is recorded
│   └── claim_file.py         # The three documents per claim
├── mcp_server.py             # MCP server: 4 resources, 4 tools, a log per claim
├── prompt.py, agent.py       # The underwriter's prompt and the tool loop
├── build/                    # Chunker, cases.json, demo and answer key builders
├── benchmark/
