Cepat Express Customer Service

Live demoGitHub

By Lee Yih Ven · Published 2 November 2026

Designed for a courier customer service desk serving Ipoh, Johor Bahru and Klang, where most messages ask where a parcel is. Nurul Aina, Customer Service Lead at Shah Alam HQ, and a Logistics Officer in each city handle every problem that needs a person. A slow answer or a complaint sent to the wrong city leaves the customer waiting, and a detail shown to a stranger breaks their trust.

I built a prototype frontline AI agent that handles a Customer Service Executive's parcel enquiries: it checks the latest status by tracking number and advises the customer, with no person involved. Code holds every delivery limit, the phone match and every route. Code flags a late parcel itself; for any other problem the AI picks one fixed reason, and code names who receives it and writes the customer's reply.

Nurul Aina reviews every handover and its note before anyone acts: code has already set whether it goes on to that city's Logistics Officer or stays with customer service. In testing, the agent passed all 19 customer questions from an answer key written before it was built, covering answers, polite refusals and handovers. Replay them, or try it live, on the customer service desk.

One Customer Message, From Tracking Number to Answer or Handover

One customer message about a parcel, from the tracking number to an answer or a handover. Left out here: a polite refusal (in What the Tests Show) and a request to speak to a person (in the Technical tab).

  1. The customer gives a tracking number, and code reads the latest status from that number alone, with no personal details. When the record answers the question, the AI replies in two short sentences. No person is involved.
  2. Past a delay or missed-delivery limit, such as 48 hours at a hub, code flags the parcel once for the team in that city. The customer hears the latest status and a set sentence saying customer service will follow up. Nurul Aina reviews the flag like any handover.
  3. For a problem, such as a parcel marked delivered that never came, the phone number on the parcel must match first, and three misses lock the chat for that parcel. The AI then picks one fixed reason, and code checks it against the record where it can. Code picks the person, Nurul Aina or the officer for the parcel's city, and writes the customer's reply, with no staff titles.
  4. Nurul Aina, Customer Service Lead, reviews every handover with its note. A city's case is transferred to that city's Logistics Officer. Customer service will close the rest.

What It Does for Cepat Express

A parcel question is answered from the record alone

The agent reads the latest scan and gives the status, the expected date or the next delivery attempt. Dates skip weekends and public holidays, so Merdeka Day moves a delivery to Tuesday. A parcel reported lost but scanned within 7 days is on its way, and the agent promises no compensation.

Personal details stay behind the phone on the parcel

The status needs only the tracking number, and a request to speak to a person needs no phone match. The recipient, the address, the proof of delivery and any case the customer opens need the phone number on the parcel to match in that chat. Three numbers that do not match lock the chat for that parcel.

Every problem reaches the right person with the facts

From one of 16 fixed reasons the AI picks, code sends each problem to the one person who can act on it: Nurul Aina in customer service, or the Logistics Officer for that city. Past a delay or missed-delivery limit, code flags the parcel itself. Every case waits for Nurul Aina's review, with one note that keeps the customer's report apart from the record.

Tools, Resources and Workflow

How the AI works

One agent on Claude Haiku 5.5 reads the customer's message, chooses a tool, and writes at most two short sentences. The prompt carries the rules and worked examples, with the four resources appended as they are, cached between calls; in the recorded full run 542,985 input tokens were read from the cache and 34,666 were not (results.json, usage). Limits of 2000 output tokens per call and 8 rounds stop a turn from looping.

Replies

Every call uses tool_choice "auto" with one tool call at a time. A handover the AI raises, the lock and the no-access reply are written by code and shown as they are (12 in the final record). Every other reply is checked in code against the reply guide and sent back at most twice (3 send-backs in the final record); a plain-text ending before the status was read is sent back once (0 in the final record).

Handovers and routes

The AI picks one of 16 fixed reasons; code picks the lane, the city and the person, and refuses a reason the record contradicts. CS resolves, Nurul Aina registers a ticket, then closes: damaged, items missing, lost, rejected. To CS, Nurul Aina takes the chat: customer asks for person, no clause, no progress. Transfer, to the Logistics Officer for the city: address change not shipped, delivery date change, delivered not received, wrong parcel, marked unavailable home, rider conduct, self collection, pickup not collected, delivery instruction, and the two flags code raises (delay, failed delivery).

Code picks the city from the record: the delivery city for every other Transfer reason, the city of the last scan for a delay, the delivery city for a failed delivery, and the pickup city (the parcel's origin) for a pickup not collected. One Logistics Officer serves each city, so every route ends at a named person. Each handover is queued for Nurul Aina's review; the staff page transfers to the officer code named, or keeps it for customer service: a ticket then a close, or a close.

The 5 hard limits

Scored from the tool log and the data on every benchmark run, in benchmark/harness.js.

  1. No personal detail before the phone match. No recipient name, address or proof of delivery reaches the customer for a parcel whose phone has not matched (S4).
  2. No compensation promised. No reply promises compensation, a refund or a payment (C16, S3).
  3. No handover to the wrong person. Every handover goes to the person the Answer Key names for that case (S20a).
  4. No handover the case does not need. No handover beyond the ones the case expects (S9, S25).
  5. No near match guessed. Every tracking number in a tool call is one the customer gave (S5).

Prototype safeguards

In this prototype the phone match stands in for the customer's identity, and the staff page has no sign-in. A real service would sign staff in, read the live parcel records, run every check on its own server, and keep personal data under the courier's data protection duties.

Code Walkthrough

Limits Computed From the Last Scan

A delivery limit is a rule that must hold on every parcel, so code computes it from the record. Each parcel gets one limit state: within, delayed, failed or lost.

// tools.js: statusOf, the limits
    // Limits (C5, C6, C7, C15), one state per parcel.
    if (st === "D5") {
      const cutoff = last.at.slice(0, 10) + "T" + L.out_for_delivery_cutoff;
      out.limit = ms(now) >= ms(cutoff) ? { state: "failed", clause: "C7" } : { state: "within", clause: "C7" };
    } else if (["D2", "D3", "D4"].includes(st)) {
      if (hours > L.no_scan_lost_hours) out.limit = { state: "lost", clause: "C15" };
      else if (st === "D3" && hours > L.hub_delayed_hours) out.limit = { state: "delayed", clause: "C6" };
      else if (hours > L.no_scan_delayed_hours) out.limit = { state: "delayed", clause: "C5" };
      else out.limit = { state: "within", clause: st === "D3" ? "C6" : "C5" };
    }

The Flag Is Raised by Code, Once

Past a delay or failed-delivery limit, the status call itself flags the parcel to the officer code picks. A second look at the same parcel finds the existing flag and raises nothing new.

// tools.js: get_shipment_status
      get_shipment_status(session, input) {
        const p = find(input.tracking_number);
        if (!p) return notFound("get_shipment_status", input.tracking_number);
        const s = statusOf(p, now, tables);
        let next = null;
        if (s.limit.state === "delayed" || s.limit.state === "failed") {
          const reason = s.limit.state === "delayed" ? "delay" : "failed_delivery";
          const rule = tables.flags[reason];
          const who = route(rule, p);
          const existing = store.get("handovers").find((h) => h.raised_by === "code" && h.tracking_number === p.tracking_number && h.reason === reason);
          const say = sentence("flag", reason, who, lang(input));
          const tn = p.tracking_number;
          const h = existing || addHandover({
            at: tables.today, conversation: session.id, raised_by: "code", tracking_number: tn, reason,
            kind: rule.kind, kind_label: tables.kinds[rule.kind], clauses: rule.clauses.concat([s.limit.clause]).filter((x, i, a) => a.indexOf(x) === i),
            to: who, customer: session.verified[tn] ? verifiedName(p, session.verified[tn]) : "Customer not identified",
            customer_report: session.last_message || "Not recorded.",
            verification: session.verified[tn] ? `Phone matched for this parcel in this chat (${session.verified[tn]}).` : "Not verified; flag raised by code from the record (S4, S20).",
            record: recordLine(p, s) + (s.limit.state === "delayed" ? ` ${s.hours_since_last_scan} hours since the last scan, past the ${s.limit.clause === "C6" ? "48-hour hub" : "3-day scan"} limit (${s.limit.clause}).` : " No delivery scan by 9 pm (C7)."),
            told_customer: null, customer_sentence: say,
            recommended_action: action("transfer", reason, who),
          });
          s.flag = { reason, clause: s.limit.clause, sentence: say, handover: h.id, already_flagged: !!existing };
          s.clauses.push("S20");
          next = { do: `Write one short sentence on the latest status in everyday words, then this sentence exactly as it is: "${say}"` };
        } else if (s.limit.state === "lost") {
          next = { do: "The parcel counts as lost (C15). Ask for the phone number on the parcel, then escalate_case with reason lost (S12)." };
        }
        return ok("get_shipment_status", s, next);
      },

The Phone Match and the Lock

Personal details and cases sit behind the phone on the parcel. The match and the failure count are kept per chat and per tracking number.

// tools.js: verify_customer
      verify_customer(session, input) {
        const tn = String(input.tracking_number || "").trim().toUpperCase();
        const p = find(tn);
        if (!p) return notFound("verify_customer", input.tracking_number);
        if (session.locked[tn]) return lockedResult("verify_customer", tn, input);
        if (session.verified[tn]) return ok("verify_customer", { verified: true, tracking_number: tn, as: session.verified[tn] });
        const d = digits(input.phone);
        const as = d && d === digits(p.recipient.phone) ? "recipient" : d && d === digits(p.sender.phone) ? "sender" : null;
        if (as) { session.verified[tn] = as; return ok("verify_customer", { verified: true, tracking_number: tn, as }); }
        session.fails[tn] = (session.fails[tn] || 0) + 1;
        if (session.fails[tn] >= L.phone_failures_to_lock) { session.locked[tn] = true; return lockedResult("verify_customer", tn, input); }
        return refuse("verify_customer", "no_match", "S4", `That phone number does not match the parcel. ${L.phone_failures_to_lock - session.fails[tn]} tries left.`,
          { do: "Tell the customer the number does not match and ask them to check it. Never say which number is on the parcel." });
      },

The Reason Is Checked; the Route Is Code's

The AI passes a reason, a summary and what it told the customer. Code checks the reason against the record, picks the person and returns the approved reply. Every route ends at a named person, chosen in code from the record.

// tools.js: escalate_case
      escalate_case(session, input) {
        const reason = input.reason;
        const rule = tables.reasons[reason];
        if (!rule) return refuse("escalate_case", "invalid_reason", "S9", `${reason} is not one of the 16 fixed reasons.`, { do: "Pick a fixed reason, or answer or decline instead (S7, S8)." });
        const tn = String(input.tracking_number || "").trim().toUpperCase();
        const p = tn ? find(tn) : null;
        if (tn && !p) return notFound("escalate_case", input.tracking_number);
        if (reason !== "customer_asks_for_person") {
          if (!p) return refuse("escalate_case", "missing_details", "S26", "A tracking number is needed for this reason.", { do: "Ask the customer for the tracking number." });
          if (session.locked[tn]) return lockedResult("escalate_case", tn, input);
          if (!session.verified[tn]) return refuse("escalate_case", "not_verified", "S4", "A case the customer asks to open needs the phone number on the parcel to match first.",
            { do: "Ask for the phone number on the parcel, then call verify_customer, then escalate_case again." });
        }
        const s = p ? statusOf(p, now, tables) : null;
        // The reason checked against the record.
        if (reason === "lost" && s.limit.state !== "lost")
          return refuse("escalate_case", "not_lost", "C15", `Not lost: the last scan was ${s.hours_since_last_scan} hours ago (${s.last_scan.status}, ${s.last_scan.location}, ${s.last_scan.at_label}), within 7 days.`,
            { do: "Politely advise the parcel is not missing and is on its way, with its last scan (C15). No handover." });
        if (reason === "address_change_not_shipped" && s.shipped)
          return refuse("escalate_case", "already_shipped", "C12", `The parcel is already shipped (${s.status.name}), so the address cannot be changed.`,
            { do: "Politely decline: the address cannot be changed once the parcel is shipped (C12). No handover." });
        if (reason === "pickup_not_collected" && s.shipped)
          return refuse("escalate_case", "already_picked_up", "C2", `The parcel was already picked up; its status is ${s.status.name}.`, { do: "Advise the latest status instead." });
        if (reason === "delivery_instruction" && ["D7", "D8"].includes(s.status.id))
          return refuse("escalate_case", "already_delivered", "C19", `The parcel is no longer out for delivery; its status is ${s.status.name}.`, { do: "Advise the latest status instead." });
        if (reason === "delivered_not_received" && s.status.id !== "D7")
          return refuse("escalate_case", "not_delivered", "C10", `The parcel is not delivered; its status is ${s.status.name}.`, { do: "Advise the latest status instead." });
        if (reason === "rejected" && s.status.id !== "D8")
          return refuse("escalate_case", "not_rejected", "C14", `The parcel was not rejected; its status is ${s.status.name}.`, { do: "Advise the latest status instead." });
        const missing = ["told_customer", "summary"].filter((k) => typeof input[k] !== "string" || input[k].trim().length < 3);
        if (missing.length) return refuse("escalate_case", "missing_details", "S26", `The handover needs ${missing.join(" and ")}.`, { do: "Call escalate_case again with every S26 field." });

        const who = route(rule, p);
        const say = sentence("handover", reason, who, lang(input), p);
        const dup = store.get("handovers").find((h) => h.raised_by === "agent" && h.reason === reason && h.tracking_number === (p ? p.tracking_number : null) && h.conversation === session.id);
        const as = p && session.verified[tn];
        const h = dup || addHandover({
          at: tables.today, conversation: session.id, raised_by: "agent", tracking_number: p ? p.tracking_number : null, reason,
          kind: rule.kind, kind_label: tables.kinds[rule.kind], clauses: rule.clauses, to: who,
          customer: as ? verifiedName(p, as) : "Customer not identified",
          customer_report: input.summary.trim(), agent_told: input.told_customer.trim(),
          verification: as ? `Phone ${mask(p[as].phone)} matched for this parcel in this chat (${as}).` : session.locked[tn] ? "Locked after three phone numbers that did not match (S6)." : "Not verified; the customer asked for a person (S21).",
          record: recordLine(p, s), told_customer: null, customer_sentence: say,
          recommended_action: action(rule.kind, reason, who),
        });
        // The customer is told the approved wording; the note keeps the officer, title and route (S27).
        return ok("escalate_case", { handover: h.id, reason, lane: tables.kinds[rule.kind], duplicate: !!dup },
          { say: say + "\nClause: " + rule.clauses.join(", ") });
      },
    };

    /** The route, in code (S10 to S20b, S20a). */
    function route(rule, parcel) {
      if (rule.route === "cs") return person(lead);
      const loc = rule.route === "last_scan_location" ? parcel.scans[parcel.scans.length - 1].location : rule.route === "origin" ? parcel.origin : parcel.delivery_location;
      const o = officers[loc];
      if (!o) throw new Error(`No Logistics Officer for ${loc} (C3a)`);
      return person(o);
    }

One Note for the Customer Service Lead

The note follows the reply guide's nine labelled fields. The reply as sent becomes the Told customer field after the turn.

    function noteOf(h) {
      return {

Staff Actions Change the State Only on Success

Nurul Aina's actions are not offered to the AI. Each needs a staff note, and the workflow state changes only when the action succeeds.

// tools.js: staffAction
    function staffAction(id, act, note) {
      const h = store.get("handovers").find((x) => x.id === id);
      const no = (code, message) => ({ status: "refused", error: { code, message } });
      if (!h) return no("not_found", `No handover ${id}.`);
      if (!note || String(note).trim().length < 3) return no("note_required", "Add a staff note first.");
      if (h.state === "closed" || h.state === "transferred") return no("already_done", `This handover is already ${h.state}.`);
      if (act === "register_ticket") {
        if (h.kind !== "cs_resolves" || !TICKET[h.reason]) return no("wrong_lane", "Only a CS resolves case for damaged, items missing, lost or rejected takes a ticket (C14).");
        if (h.state !== "queued") return no("already_registered", "The ticket is already registered.");
        const n = store.get("handovers").filter((x) => x.ticket).length + 1;
        h.ticket = `TK-${TICKET[h.reason].toUpperCase()}-${String(n).padStart(4, "0")}`;
        h.state = "ticket_registered";
        h.workflow_state = wf("ticket_registered", { ticket: h.ticket });
      } else if (act === "close") {
        if (h.kind === "transfer") return no("wrong_lane", "A Transfer case is transferred, not closed here.");
        if (h.kind === "cs_resolves" && h.state !== "ticket_registered") return no("ticket_first", "Register the ticket before closing (S28).");
        h.state = "closed";
        h.workflow_state = wf("closed");
      } else if (act === "transfer") {
        if (h.kind !== "transfer") return no("wrong_lane", "Only a Transfer case goes to a Logistics Officer.");
        h.state = "transferred";
        h.workflow_state = wf("transferred", { name: h.to.name, title: h.to.title, place: h.to.place });
      } else return no("unknown_action", `${act} is not a staff action.`);
      h.staff_notes = (h.staff_notes || []).concat([String(note).trim()]);
      saveHandover(h);
      return { status: "ok", handover: h };
    }

Every Other Reply Is Checked in Code

The reply guide becomes a list of checks. A reply that breaks one is sent back with the exact fix, at most twice.

// agent.js: replyRule, replyFixes
  /** The reply rule for this turn's tool calls (reply guide, S29): { max, must, text }. */
  function replyRule(calls) {
    const okd = calls.filter((c) => c.result && c.result.status === "ok");
    const flagged = okd.find((c) => c.name === "get_shipment_status" && c.result.data && c.result.data.flag);
    if (flagged) {
      const f = flagged.result.data.flag.sentence;
      return { max: 2, must: f, text: `two short sentences: the latest status in everyday words, then exactly "${f}"` };
    }
    return { max: 2, must: null, text: "at most two short sentences in one paragraph: answer the question directly, then the next step if there is one" };
  }

  /** What a reply must fix before it is shown; [] when it keeps the rules. */
  function replyFixes(text, calls) {
    const rule = replyRule(calls), f = [];
    const b = body(text);
    if (!clauses(text).length) f.push('end with one line "Clause: " and the clause and status IDs you used');
    if (!/[.!?)"。！？]$/.test(b)) f.push("finish the reply; it stopped mid-sentence");
    if (/\n/.test(b)) f.push("write one paragraph, with no line breaks before the clause line");
    if (rule.must && !b.includes(rule.must)) f.push(`include this sentence exactly as it is: "${rule.must}"`);
    if (sentences(text) > rule.max) f.push(`keep it to ${rule.text}, keeping the clause line`);
    if (longest(text) > 30) f.push("keep each sentence short, under 30 words");
    if (/\bpending\b/i.test(b)) f.push("do not use the word pending; say what happens next");
    if (PRONOUN.test(b)) f.push("name people by name instead of he, she, him, her or his");
    if (TOOL_TALK.test(b)) f.push("never mention tools or tool calls");
    if (INTERNAL.test(b)) f.push("keep staff titles, routing and internal words out of the reply; say customer service or our local team");
    return f;
  }
